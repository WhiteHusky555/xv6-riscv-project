# Подсистема Ядра (Kernel Space)

Данная директория содержит исходный код монолитного ядра операционной системы xv6-riscv, модернизированного для поддержки многопроцессорности, многопоточности и неблокирующего ввода-вывода.

## Архитектура и ключевые модули

* **`proc.c` / `proc.h`**: Сердце подсистемы управления процессами. Здесь реализованы системные вызовы `clone()` и `join()`, логика распределения потоков, а также цикл планировщика `scheduler()` с поддержкой энергосберегающей инструкции `wfi`.
* **`kalloc.c`**: Параллельный аллокатор физической памяти. Глобальная блокировка заменена массивом структур `kmem[NCPU]`, выделяющим каждому ядру собственный независимый список свободных страниц (`freelist`) с поддержкой механизма распределения нагрузки (page stealing).
* **`khashtable.c`**: Высокопроизводительная потокобезопасная хеш-таблица ядра (`map<uint, uint>`), использующая комбинацию сегментированных блокировок (8 изолированных спинлоков) и паттерна Copy-on-Write (CoW) для бесконфликтной параллельной работы.
* **`uart.c` / `console.c`**: Модули низкоуровневого драйвера ввода-вывода. Переведены из событийного режима обработки прерываний в режим циклического опроса (Polling) с оптимизацией планирования через ассемблерный вызов `asm volatile("wfi")`.
* **`trap.c`**: Обработчик ловушек, прерываний и системных вызовов. Модифицирован для изоляции контекстов потоков (использование регистра `sscratch` для динамической адресации `trapframe_va`). Также диспетчеризует `VIRTIO1_IRQ` в `virtio_net_intr()`.
* **`virtio_net.c` / `net.h`**: Драйвер сетевой карты virtio-net (второй слот virtio-mmio шины, `VIRTIO1` в `memlayout.h`, следом за диском на `VIRTIO0`). Реализует уровень 5.6.2 учебника xv6 — только Ethernet-кадры, без стека TCP/IP. Верхняя часть драйвера (`net_tx`/`net_rx`/`net_getmac`, системные вызовы `netsend`/`netrecv`/`netmac`) работает через одну блокировку `net.lock` и `sleep`/`wakeup` по правилам главы 7; нижняя часть — обработчик прерывания `virtio_net_intr()` — освобождает TX-дескрипторы и складывает принятые кадры в программную RX-очередь, немедленно возвращая аппаратный буфer устройству. DMA-буферы (`net_rxbuf`, `net_txbuf`, `net_txhdr`) — статические массивы в `.bss`, а не на стеке ядра: раздел 3.2 учебника явно требует прямого отображения (VA==PA) для памяти, которую читает/пишет устройство, а `KSTACK` в этом ядре живёт по отдельному невыровненному адресу.

## Модернизация и устраненные гонки (Race Conditions)

1.  **Синхронизация таблиц страниц**: В функцию `growproc()` внедрена строгая (eager) аллокация кучи через `uvmalloc()` под защитой спинлока `wait_lock`. При изменении размера памяти ядро синхронизирует ядерные таблицы страниц (`kpagetable`) всех родственных потоков через процедуру `u2kvmcopy()`.
2.  **Атомарный Sleep**: Проверка флага `p->killed` внутри механизма засыпания перенесена под защиту блокировки процесса `p->lock` непосредственно перед передачей управления планировщику, что полностью закрыло уязвимость "потерянного сигнала" (Lost Wakeup).
3.  **Безопасный возврат из Trap**: Использование индивидуальных виртуальных адресов `p->trapframe_va` исключило взаимное затирание регистров CPU параллельно выполняющимися потоками одного процесса.
